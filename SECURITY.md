# Security baseline — KSCW website (`kscw-website`)

Static Astro 6 site on Cloudflare Pages (`kscw.ch`). Client behaviour via `public/js/*.js` + `src/islands/*.ts`. Data is fetched at build time and client-side from the **shared Directus backend** (`directus.kscw.ch`, repo `wiedisync` — its own `SECURITY.md` governs the API). There is a real admin page at `src/pages/admin.astro` (CRUD against Directus via the `/kscw/wadmin/*` server-validated endpoints).

## Trust boundaries

- The site is a **public static asset** — anything shipped to `dist/` is world-readable. No secret/token is embedded in the bundle (verified). The admin page's client-side gate is cosmetic; every privileged read/write is re-authorized server-side by `/kscw/wadmin/*` + Directus permissions, with the Directus token obtained via a runtime login form and held in `sessionStorage`.
- Minor (under-18) PII protection lives **upstream** in the Directus `/kscw/public/team/:id` endpoint (underage teams return an empty roster; every other roster is `isMinor(birthdate)`-filtered fail-closed). The website renders only what that endpoint returns — it must never call a wider members API for public pages.
- CORS: this repo emits **no** `Access-Control-Allow-Origin` header (verified across `src/`, `public/`, `dist/`, `functions/`, git history). The static site is not cross-origin-readable by default.
- **Scorer-exam upload** (`/weiteres/schreiberkurse/pruefung` + `public/js/scorer-exam-upload.js`) is the site's only **anonymous write** of a file. The page decides nothing: `POST /kscw/scorer-exam/lookup` (Turnstile + per-IP limit) checks the typed email against the scorer courses' OpnForm sign-up lists and **emails that address** a link back to this page carrying a 24-hour HMAC ticket (`#ticket=…`, in the fragment so it never reaches a server log); `POST /kscw/scorer-exam/ticket` returns what the page shows for a valid ticket; `POST /kscw/scorer-exam/upload` accepts bytes only for a valid ticket. See `wiedisync/.../scorer-exam.js` for the model. Consequences worth knowing:
  - The gate is **control of the registered mailbox** (2026-09-28 audit). Until then `/lookup` returned the ticket to the browser, so anyone who knew a participant's email could upload in their name, and its 404 confirmed whether an address was registered. Now `/lookup` answers `{ ok: true }` for every address (sent before any mail, so timing does not leak a match either), caps link mails per recipient silently, and never returns a ticket, name or licence number. The page reads the ticket from the fragment and `history.replaceState`s it away immediately. An admin still reviews every sheet before ticking "bestanden" — an upload is a claim, not proof.
  - Uploaded scoresheets are **personal data** and MUST stay in `SCORER_EXAM_FOLDER`. The Directus Public file policy grants `/assets` reads to **folder-less files only**, so the folder assignment *is* the privacy boundary; `folder: null` would make a sheet world-readable by id. Admin reads go through `/kscw/wadmin/scorer_courses/assets/:id`, which additionally requires the id to be referenced by a `scorer_course_attendance.exam_file` **or `exam_file_corrected`**. Verified on dev: anonymous `/assets/<id>` → 403, unrelated file via wadmin → 404.
  - The file **type is sniffed from the leading bytes**, never trusted from the filename or `Content-Type`, so HTML named `.pdf` cannot become stored XSS in an admin's browser. **HEIC is refused** (2026-07-17) — not a security call: nothing downstream decodes it, so it could be neither previewed nor converted for the SVRZ bundle.
  - **Admin scoresheet corrections** (2026-07-17) — `POST /kscw/wadmin/scorer_courses/scoresheet-correction/:slug/:id` lets an admin upload a corrected sheet. Authenticated + `scorer_courses`-scoped (`guardScorer`), and it reuses the participant route's `sniffType` + 10 MB cap by import rather than by copy, so the two cannot drift. Writes `exam_file_corrected` only — **never** `exam_file`, so the participant's own submission is never overwritten by an admin edit. The attribution (`exam_file_corrected_by`) is resolved server-side from the session user and is **not accepted from the request body**; a client-supplied name would be decoration, not a record.
- **Signups filed from `/admin`** (2026-09-04) — `POST /kscw/wadmin/scorer_courses/opnform/forms/:slug/submissions` creates a real form response for a latecomer. Authenticated + `scorer_courses`-scoped (`guardScorer`, which also binds the slug to a `scorer_courses` record for non-superusers). Two capabilities no other wadmin route has, both deliberate, both logged with the calling user:
  - **It sends mail to an address the caller supplied.** OpnForm has no admin route that creates a submission, so this posts to the form's own public `answer` endpoint — which is what makes the entry a genuine signup, and what fires the form's notification integrations (the participant, plus `scorer@volleyball.kscw.ch`). It is the same power the public form already gives anyone who can open it, aimed at the club's own course forms only. `/admin` leaves it **unticked by default**; unticked, the signup is stored in `scorer_course_attendance` and no mail is sent.
  - **With `reopen_if_closed` it lifts the form's `closes_at` for the length of one POST**, because `FormPolicy::answer` refuses a closed form and a hand-added signup is almost always late. Opt-in only — `/admin` asks in as many words and never assumes it — and the deadline is restored in a `finally`. If the restore fails the route answers `form_left_open` and logs at **error** level: a live registration form standing open is for a human to close, not a warning to scroll past.
  - Answer keys are checked against the form's own field ids (an unknown key is refused, not written), values are capped at 2000 chars / 50 list items, and `submission_id` / `submission_hash` are refused outright — with `editable_submissions` on, either would make `answer` **overwrite an existing signup** instead of creating one.

## Hardening completed (audit log)

Deduplication shield — if a future audit re-finds one of these, it's a regression or a misunderstanding.

### 2026-09-28 — Second dual-repo audit (website + the wiedisync endpoints it trusts)

Findings F-01…F-66 of the 2026-09-28 audit (security, permissions, logic). Backend detail lives in `wiedisync/SECURITY.md` (same date); this block records what the website depends on and what changed here. **Deploy order matters:** wiedisync migration 381 → extensions (`/kscw/public/feedback`, `/kscw/public/form-upload`, `/kscw/registration/upload-ticket`, the wadmin routes below) → `setup-perms` (Public `news.is_published` readable) → **then** this site. The website now sends `filter[is_published]` and posts feedback to the new endpoint; deployed first, the news query 403s as a whole and the feedback form fails closed.

**Backend the site trusts (wiedisync):**
- **Personal uploads out of the public root (F-01/F-02/F-03, high).** Anonymous `POST /files` is gone; anonymous `GET /files` listing is refused by a `files.query` hook (`/assets` for public images keeps working); receipts, form file answers and feedback screenshots land in private folders. The website had already stopped using the anonymous upload grant (registration goes through `/kscw/registration/upload`).
- **Registration upload (F-09).** Type sniffed from the bytes, a rolling-24h byte budget for the folder, per-/64 IPv6 limits, and an HMAC upload ticket that `registration-form.js` now fetches from `/kscw/registration/upload-ticket` after Turnstile (`anmeldung-dokumente` gets one via ref+email). Unticketed uploads are still accepted against a smaller budget until `REGISTRATION_UPLOAD_REQUIRE_TICKET=true` — see the open row below.
- **wadmin field write policy (F-04/F-05).** The generic CRUD refuses `scorer_course_attendance.exam_file*` for everyone (only the upload route sets them) and `scorer_courses.form_slug_*` changes for non-superusers — which closes mailing an arbitrary file (e.g. an ID scan) to oneself, deleting arbitrary files and repointing `guardScorer` at any OpenForm form. New narrow routes replace UI paths that bypassed wadmin: Mixed-Turnier participants (F-10, `members`/`participations` stay out of the generic CRUD) and registration documents view/download/delete bound to the registration folder (F-21).
- Also: officials honour `website_name_private` (F-06); archived/draft news no longer public (F-07); scorer re-upload after grading → 409 `already_graded` (F-14; the licence number never reaching the browser, F-15, is covered by the emailed-ticket flow's `licence_on_file`); guests, trainings and team notes filtered server-side on the public team endpoint (F-35/F-36); fail-closed shared Turnstile verifier with hostname pin (F-27); Public `events` read dropped and `hall_slots`/`halls` field-scoped (F-38/F-61); error-log budget, password-reset, newsletter enumeration, OpenForm count, fee-category and mail-relay hardening (F-16/F-17/F-22/F-32/F-33/F-34/F-37/F-59/F-60/F-66); bugfix triage shows anonymous-vs-authenticated provenance and ranks by occurrences an attacker cannot mint (F-13, backend half).

**This repo:**
- **Open redirect on the legacy locale URLs (F-40).** `/de/*  /:splat  301` turned `/de//evil.example` into `Location: //evil.example`. `_redirects` cannot normalise a splat, so every `/de` and `/en` rule moved into `functions/_middleware.js`, which collapses any run of `/` and `\` (raw or percent-encoded) and builds an absolute same-origin Location by concatenation, never `new URL(path, …)`. `public/_routes.json` limits Functions to `/de`, `/de/*`, `/en`, `/en/*`. Not yet verified at the edge — run `curl -sI https://kscw.ch/de//evil.example` after the deploy and expect `Location: https://kscw.ch/evil.example`.
- **Expired middleware (F-43).** The `kscw-website.pages.dev` → kscw.ch 302 (window closed 2026-07-08; kscw.ch is now served by `kscw-web`) is removed. With `_routes.json`, a normal page view no longer invokes a Function.
- **CSP names exact CDN files (F-62).** `script-src` / `style-src` allowed all of `unpkg.com` and `cdn.jsdelivr.net`, i.e. every npm package ever published. Now it lists the six files actually loaded (quill 2.0.3 js+css, DOMPurify 3.2.4, pdf-lib 1.17.1, leaflet 1.9.4 js+css), and neither CDN appears in `connect-src`. `tests/unit/edge-ci.test.ts` cross-checks every CDN URL in `src/` and `public/` against the policy in both directions. `quill.snow.css` now carries SRI as well (F-63).
- **Deploy pipeline (F-42/F-44).** The live deploy runs `npm run build`, so the `prebuild` Seitentexte bake happens (it used `npx astro build`, which skips it). `test.yml` is now called by the deploy workflow as a `needs:` job, so a push that fails the CSP/XSS/site-text suites never deploys; only the two test-login secrets are passed to it, not the Cloudflare token.
- **Bugfix-AI workflow (F-13).** `error_context` is text an anonymous visitor can shape. The agent job now holds a read-only token, keeps no git credentials (`persist-credentials: false`), gets its tools through v1 `claude_args --allowedTools` (Read/Write/Edit/Glob/Grep only, Bash explicitly disallowed; the old `allowed_tools`/`model` inputs were silently ignored by v1) and reads the context from a file rather than a shell. Not even `Bash(npm run build)`: the agent can edit `package.json`/`astro.config.mjs`, so a build it runs is an arbitrary command next to `ANTHROPIC_API_KEY`. The verification build is a separate step with no secret in its environment. A separate job with write permissions applies the patch, refuses any patch touching `.github/`, and opens the draft PR on `bugfix/<hash>`. A superuser still clicks Fix and Deploy, and a human merges.
- **Admin page.** No draft titles are sent to MyMemory any more: translation happens only on button press, and the result lands in an editable field (F-28). The direct `/users` read went with the event form's junction writes (F-23), and `quill.snow.css` now carries SRI like the three admin scripts (F-63) — together they close the WEB-ADM-2 residual. Logout revokes the refresh token (F-64), refresh is single-flight (F-65), TSV cells are formula-neutralised (F-19), mailto addresses are validated and encoded (F-20), the verdict mail waits for a stored verdict (F-18), lists page through (F-24), and event signups are superuser-only (F-25). `form_slug_*` is sent only by a superuser and only when edited, so saving an unrelated field never rewrites a stored slug; a 403 `field_not_writable` and a 409 `result_not_saved` (verdict not on record → no mail) are shown as what they are, not as a success (C5 / F-18). The dashboard reads its backend from `window.__KSCW_DIRECTUS`, set in its own `<head>` with the same two-host allowlist as `BaseLayout` (F-41).
- **Admin login captcha removed (F-26).** The Turnstile widget sent `X-Turnstile-Token`, but nothing on Directus verified it on `auth.login`, so it was decoration that also cost every login a third-party script. **If a Turnstile check on `auth.login` is ever added (a `kscw-hooks` filter), the widget, its site key and the token header must come back in `admin.astro` in the SAME change** — deployed alone, the filter refuses every admin login, and deployed without the filter, the widget is decoration again. Until then brute-force protection is Directus' own (see the open row below).
- **Registration documents never render in the kscw.ch origin (F-21, blob-origin rule).** `/admin` fetches ID scans and `bb_doc_*` PDFs through `/kscw/wadmin/registrations/files/:id` with the token and turns them into a `blob:` URL. A `blob:` document runs in the page's own origin under the page's CSP (`'unsafe-inline'`) and without the `sandbox` CSP the Directus route puts on the file — so an applicant-uploaded SVG/HTML "ID scan" opened in a tab would run as kscw.ch next to the admin token in sessionStorage. Rule: **only `image/png|jpeg|gif|webp|avif` may be opened inline, and the blob is re-created with that allowlisted type; everything else — PDF included — is re-typed `application/octet-stream` and downloaded** (`registrationFileDisposition()` in `admin.astro`, pinned in `tests/unit/admin-audit-2026-09-28.test.ts`). Never open a blob built from the server's Content-Type. The scorer-exam scoresheet viewer (`scoresheetAsPdf()`) follows the same rule: PDFs and converted images open as `application/pdf`, and its undecodable-file fallback is re-typed through `registrationFileDisposition()` rather than keeping the served type.
- **Public runtime.** The feedback form posts to `/kscw/public/feedback` instead of multipart `/items/feedback`, which silently dropped every field (F-08); the Turnstile token stays in `X-Turnstile-Token`, only `{ok:true}` counts as success, and server error text is never shown to the visitor. Query strings and fragments are stripped from the Sentry event URL, the Referer header, breadcrumb URLs, and URLs inside messages/exception values (so no `?ticket=`, `?ref=&email=` or verify token reaches Sentry), and `anmeldung-dokumente` clears ref+email from the address bar once read (F-29). Newsletter verify/unsubscribe links report a 4xx as an invalid link and the Turnstile token is reset on failure (F-30/F-31); the subscribe form has a single outcome ("check your inbox"), matching the server's uniform answer (F-59 — the `already_subscribed` branch is gone). The scorer-exam upload page (emailed-ticket flow, 205df80) maps a 409 `already_graded` to its own DE/EN message and, when `/ticket` reports `graded`, says so up front and disables the upload (F-14). `safeHref` (both the browser copy `public/js/safe-href.js` and `src/lib/safeHref.ts`) refuses any href starting with two slashes or backslashes in any mix (`\\`, `/\`, `\/`), which browsers resolve as protocol-relative, i.e. off-site (F-58). Hall `maps_url` — admin-authored Directus data — now goes through `kscwSafeHref` in `game-modal.js` (no link if the guard is missing) and `safeHref` in `calendar-grid.ts` (PR-5). Preview builds talk to the Directus they were built against, and the live hosts are pinned to prod (F-41). The remaining logic fixes are F-11, F-12, F-46–F-57.

### 2026-08-11 — Who may hold a website-admin grant, and the client gate that contradicted it

- **Eligible roles are now a set, not one string.** `wadmin.js` gated on `role.name === 'website admin'` exactly, so a person could only administer the website by *being* a Website Admin. A Directus user has one role, so the club's youth/sport administrators (`Sport Admin`, needed for their actual work in Wiedisync) could not be given so much as page-text access without surrendering it. `GATED_ROLES = {'website admin', 'sport admin'}` replaces it. **Eligibility is not access**: the per-user row in `website_admin_access` is still the only thing that opens a section, and a Sport Admin with no row gets `[]` — pinned by tests, including that a stray row against an *ineligible* role stays inert.
- **`/wadmin/admins` lists every eligible role.** It filtered on the same single role name, so a Sport Admin who *had* been granted sections would have been invisible in the superuser's grant grid — granted access that nobody could see or revoke from the UI.
- **The admin page's client gate now asks the server.** `isAuthorized()` in `admin.astro` compared `role.name` against a hardcoded list (`website_admin`, `website admin`, `admin`, `administrator`, `superuser`). That made it a second source of truth for one decision, and it did not contain `sport admin` — so a person holding a valid grant would have been shown "Zugang verweigert" by the client while the server happily authorized their every request. It now gates on `/kscw/wadmin/me` (`isSuperuser || sections.length > 0`), the same authority that re-authorizes each data call, so adding an eligible role needs no website change at all. Still cosmetic in the security sense: it decides what renders, never what may be read or written.
- Unchanged: the wadmin routes reach data through an admin-accountability `ItemsService` that bypasses RLS, so a granted section works regardless of what the holder's own Directus role permits. That is what makes the grant row load-bearing — and why widening eligibility is a deliberate decision rather than a tidy-up.

### 2026-08-11 — Content overlay Phase 1: the page-text editor (`/admin` → Seitentexte)

The write path Phase 0 was hardening for. An admin can now edit any string the site renders, from the browser. New trust boundary: **a dictionary value is no longer developer-authored.** What keeps that safe:

- **Overrides only, never a replacement.** `site_text` (migration `309-site-text.sql`, `wiedisync`) holds one row per edited key; the repo dictionaries stay the original wording and the fallback. A language left unedited is stored as `NULL`, not as a copy of the default — so a later improvement to that language in the repo is not silently shadowed by a stale copy. Deleting the row restores the shipped text, which means no browser action can permanently lose the original.
- **Text only, enforced in four places** so no single omission opens a hole: the endpoint (`kscw-endpoints/src/site-text.js` — refuses `<`, control characters, non-strings, >2000 chars), the table's `CHECK` constraints (same rules in the database, for any future write path that forgets), the build (`scripts/fetch-site-text.mjs` drops anything with markup, an unknown key, or a lost `{placeholder}`), and the browser (`public/js/i18n.js` applies values with `textContent`/`setAttribute` only and re-checks before applying). `tests/unit/no-i18n-html.test.ts` already forbids the `innerHTML` path that would make any of this exploitable.
- **Writes bypass the generic wadmin CRUD.** `site_text` is in `ALL_SECTIONS` (so it can be granted per-user) but deliberately **not** in `SECTION_COLLECTIONS`, so `/wadmin/site_text/items/site_text` returns `resource_out_of_scope`. The only way in is `PATCH/DELETE /kscw/wadmin/site_text/text/:key`, which validates. `wadmin.test.js` pins that asymmetry so a future "tidy-up" cannot quietly restore the unvalidated path.
- **Keys are shape-checked before reaching a selector.** The runtime overlay interpolates the key into `[data-i18n="…"]`, so `^[A-Za-z][A-Za-z0-9_]*$` is enforced at the endpoint, in the database, and again in the browser — a key carrying a quote or bracket cannot widen that selector.
- **The public read is anonymous by design** (`GET /kscw/site-text`, `max-age=30`): it returns website copy that is already visible on the pages it belongs to. It is served from a table with **no Directus collection registration**, so there is no `/items/site_text` REST surface and no public policy to grant — same posture as `website_admin_access` (063).
- **Availability, not just confidentiality.** The overlay is never awaited: `public/js/i18n.js` starts the fetch alongside the dictionary but the loading veil, `window.i18nReady` and first paint never depend on it, and the build script keeps the last known overrides and exits 0 on any failure. Directus being down costs the committed wording, never a blank or undeployable site.
- **Admin's own chrome is out of scope.** `admin.astro` is excluded from the manifest, so the editor cannot be used to rename the buttons needed to undo an edit.
- Unchanged and accepted: text typed here is sent to `api.mymemory.translated.net` when the admin presses "Übersetzen" (same third party, same reasoning as the news/event title translation — this is public website copy).

### 2026-08-08 — Content-overlay Phase 0 (prerequisite hardening, no CMS surface yet)

Standalone hardening that had to land **before** any admin-editable-content write path exists. Useful on its own — it closes a live hole and a latent one.

- **`javascript:` URL execution via sponsor `website_url` — live, not theoretical.** `sponsors.website_url` is admin-authored and reached `a.href` unvalidated in three places: `src/pages/sponsoren/index.astro` (build-time), the `is:inline` sponsor carousel in `src/pages/index.astro`, and `public/js/team-page.js`. Because `script-src` carries `'unsafe-inline'` (deferred below), a `javascript:` value executed on click. Now vetted by a scheme allowlist — `safeHref()` in `src/lib/safeHref.ts` for build time, its runtime twin `public/js/safe-href.js` (`window.kscwSafeHref`, loaded render-blocking from `BaseLayout`'s `<head>`) for the two browser contexts that cannot import a module. Both **fail closed**: a rejected URL renders an unlinked element, never an unvetted `href`. The guard strips the characters a URL parser ignores (NUL/TAB/LF/CR) and expands numeric character references first, so `jav&#x09;ascript:` and `jav<TAB>ascript:` cannot smuggle a scheme past it; protocol-relative `//host` is refused explicitly. `tests/unit/safe-href.test.ts` (72 cases) runs one corpus through **both** implementations and asserts they agree, so the pair cannot drift.
- **`team-page.js` external `logo_url` passthrough.** `logoRef.indexOf('http') === 0` also accepts `httpfoo:`; the external branch now goes through the same guard and falls back to the club shield when refused.
- **`data-i18n-html` deleted entirely.** Two call sites (`club/kontakt.astro`, `club/feedback.astro` — the same privacy-consent sentence) plus the `innerHTML` loop in `public/js/i18n.js`. Each sentence is now three sibling `data-i18n` nodes. This had to precede any write path: the resulting stored XSS would have been **English-only**, since German renders through Astro's auto-escaping at build, so a German-speaking reviewer clicking the whole site would have seen nothing wrong.
- **Dictionary values can no longer carry markup.** The keys whose values contained `<strong>`/`<a>` were the confirmed-dead `basketballTeamsNachwuchs*Training` and `*HallLabel1-3` plus three duplicate consent strings; all removed, with zero remaining references.
- **`loadTranslations` had no `.catch`.** A failed dictionary fetch left `window.i18nReady` permanently unsettled — team pages, the calendar, scorer courses and youth status all await it, so a transient failure rendered a **blank** page rather than a degraded one. Both the init and language-switch paths now resolve and unveil on failure.
- **Cache-busting for the files that carry these fixes.** `js/i18n.js`, `js/team-page.js` and `js/safe-href.js` are served `max-age=14400`; all three now go through `versionedAsset()` so a security change reaches returning visitors immediately instead of up to four hours later.

### 2026-06-25 — First dual-repo deep audit (security + permission + UI)

Audited alongside `wiedisync` (see `wiedisync/SECURITY.md` same date). Remediated:
- **Stored-HTML injection into the admin DOM (WEB-ADM-3).** `mixed_tournament_signups.notes` (filled by an unauthenticated public visitor) was injected with `innerHTML` after a **default-profile** DOMPurify pass, which permits `<a href>`/`<img src>` — a phishing-link / tracking-beacon vector in the admin's browser. Now rendered with the file's `escapeHtml()` (plain text).
- **`set:html` foot-gun (WEB-SEC-3).** `SectionHeader.astro` rendered its action label via `set:html`; changed to plain `{actionLabel}` interpolation (auto-escaped).
- **Fragile success-modal HTML (WEB-SEC-7).** `registration-form.js` / `mixed-tournament-form.js` / `volley-feedback-form.js` built the success message via `innerHTML` string concat; rebuilt with `createElement` + `textContent` so the message can never be interpreted as HTML.
- **DOMPurify vendored locally (WEB-SEC-4).** The news-body XSS sanitizer was loaded from `cdn.jsdelivr.net` (SRI-pinned + safe escape-only fallback). Vendored the SRI-verified DOMPurify 3.2.4 to `public/js/vendor/purify.min.js` and repointed `index.astro` + `news/index.astro`, so the sanitizer no longer depends on a third-party CDN's availability.
- **UI/a11y (UI-WEB-1..8).** Desktop nav dropdowns are now keyboard-operable (`:focus-within` + `aria-haspopup`/`aria-expanded` + Enter/Space/Escape handling); mobile accordion + hamburger keep `aria-expanded` honest; the language toggle uses `aria-pressed` (was a non-semantic `radiogroup`); lang/admin/search icon buttons get a ≥44 px coarse-pointer hit area; the English locale (`public/js/i18n/en.json`, 238 values) + standalone German "Optional" labels were corrected to Sentence case.

## Audit cadence

Re-run the deep audit (see `wiedisync` `/kscw-security-audit` skill, extended to this repo) on a milestone bump, a new admin capability, or a new outbound integration. Append a dated block above and move items between the two sections.

**Also sweep credentials when an integration is _removed_.** Deleting the code does not revoke the token, and the two live in different places (repo vs. Cloudflare Pages env vars vs. the vendor's own console) — see the TinaCMS row above, where a credential outlived its integration by ~5 months. On removal: delete the env vars **and** revoke at the issuer **and** record it here.
